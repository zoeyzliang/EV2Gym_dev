Limitations & Caveats

DOE compliance anomaly (open issue)

SAC-Flat, Greedy, RulePrice, and OracleMPC all showed exactly 0.0% DOE compliance in an earlier evaluation pass. Root-cause investigation traced part of this to a genuine bug: the alpha entropy-temperature clamp intended to prevent SAC-Flat's policy from collapsing only bounded a local derived copy, not the underlying log_alpha parameter actually being optimised — fixed by clamping the parameter in-place after each optimiser step.

After this fix, SAC-Flat's DOE compliance is no longer exactly zero but still plateaus well below SAC-GNN/SAC-GCN's near-100% compliance (training logs show violation dropping from ~228,000 kW early in training to a plateau in the 65,000–180,000 kW range, never reaching the near-zero compliance the graph-based agents achieve). This is consistent with the architectural hypothesis motivating RQ3: without graph-based message passing, a flat MLP has no mechanism for spatial credit assignment across the 21 hubs' correlated DOE constraints.

Greedy's 0% compliance is expected by construction — it dispatches at full equipment capacity with no DOE awareness at all, by design as a naive baseline.

OracleMPC and RuleBasedPricing both contain explicit DOE-respecting logic in their implementation (e.g. OracleMPC computes effective dispatch bounds as min(DOE_limit, equipment_cap)), so their 0% compliance is inconsistent with their own source code and remains an open, unresolved issue at the time of this report. Results for these two agents should not yet be treated as final — recommend tracing the DOE-limit denormalisation path in oracle_mpc.py and rule_based_pricing.py before reporting their profit figures as conclusive.

Validation/test split

SAC-GNN and SAC-GCN checkpoints reported here were selected during training using an earlier validation scheme that was later found to reuse conceptually similar (though not identical) scenario categories to the final test set. SAC-Flat was trained under a corrected, leak-free validation/test split with zero date overlap. All final numbers in this report come exclusively from the held-out test set (CASE_STUDIES in evaluate.py), which was never used for checkpoint selection for any agent — see train_sac_gnn.py's VALIDATION_DAYS documentation for full detail.

Sample size

n=30 runs per (agent, case study) pair. A larger n (the field precedent of Orfanoudakis et al. 2025, Communications Engineering, uses n=100) would further tighten confidence intervals, particularly for the high-variance stress-test case study.
